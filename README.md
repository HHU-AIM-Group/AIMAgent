# AIM Radar · 多模态研究周报

团队成员在自己的电脑运行这个网站，使用自己已经登录的 Codex，为团队五个研究方向发现本周论文、公开投稿、会议论文集更新与重要产业动态。研究画像来自 [团队公开网站](https://multimodality.group/)。页面中的关联解释和行动建议属于分析判断；题名、链接、日期及来源保留抓取事实，方便回溯核验。

## 启动

需要 Python 3.9 或更新版本，无需安装第三方依赖。

- macOS：解压后双击 `启动 AIM Radar.command`。若系统阻止打开，可在终端进入文件夹运行 `bash start.sh`。
- Windows：安装 Python 后双击 `start.bat`（已提供启动脚本，本次未在 Windows 实机验证）。
- Linux 或终端：在项目文件夹运行 `python3 launch.py`；只启动服务可使用 `python3 app.py`。

启动脚本会自动打开浏览器，默认地址为 **http://127.0.0.1:8765**；若端口已被其他应用占用，会选择 8766–8785 中的空闲端口，实际地址显示在启动窗口。启动窗口需要保持打开；按 Ctrl+C 停止。服务仅监听本机，每名成员各自运行一份。

## 连接自己的 Codex

先安装并登录 Codex CLI，或使用 Codex 桌面应用提供的 CLI。网站会检查常见路径；也可在设置中填写 Codex 可执行文件的绝对路径，点击连接测试。网站复用 CLI 已保存的登录状态，不收集密码或令牌。默认模型为 `gpt-6.1-sol`，可在设置中调整。

点击“生成周报”开始抓取和分析。使用 Codex 会消耗当前登录账号的模型额度。若连接或模型分析失败，系统保留真实抓取结果，并明确显示规则匹配回退与失败原因。

每次最多选择 24 条重点候选交给 Codex，兼顾五个研究方向和产业动态；其他真实抓取条目继续保留规则初筛标签。卡片和报告会显示实际分析范围，避免把全部采集内容误认为都经过模型分析。

## 本周与来源

默认本周按 **Asia/Shanghai（UTC+8）周一到今天**，也可选择最多 14 天的区间。结束日期包含当天。不同来源的“本周”含义会单独标注，不能把推荐或发现日期当成首次发表日期。

- **Hugging Face Daily Papers**：按每日推荐日期发现论文；可能推荐早已发表的论文，因此保留原论文日期与推荐日依据。
- **arXiv**：发现窗口内首次提交或更新的相关预印本；同一 arXiv 论文的不同版本合并，保留来源链接。预印本不等于会议录用。
- **OpenReview**：补充配置会议的公开投稿；首次公开日期依据 `odate`，带有明确录用状态的记录才可按 `pdate` 标记本期录用。缺少首次公开日期时只标记更新或本机首次观察，不把创建时间当成公开时间。公开接口覆盖受会议权限、访问验证与届次配置限制。
- **会议论文集**：检查官方发布页的变化。第一次运行建立基线，不把页面中全部历史论文集宣称为本周新增；后续可识别新观察到的发布链接，仍需核验官方发布时间。
- **产业新闻**：检查预置官方 RSS/Atom 来源及设置中的公开 HTTPS 补充订阅。覆盖范围以每次报告的来源状态为准，不能保证所有行业动态均被收录。

失败、未启用、成功但无结果是三种不同状态。某个源失败时，其他来源仍会继续，报告标记为部分完成。周报的自动摘要与建议基于公开摘要或公告；需要核对全文时，使用下方的单篇功能。

## 五个方向

遥感多模态基础模型及下游适配；无人机多模态环境感知与世界动作模型；预训练基础模型的小样本下游泛化；多模态大模型幻觉抑制；标签噪声关联学习。RemoteCLIP、RemoteSAM、RemoteReasoner、RemoteAgent、RemoteShield、RemoteDescriber、AirNavigation、UEMM-Air 等团队成果只作为相关性匹配背景。

可编辑 `config/profile.json` 的方向描述、关键词与背景工作，自定义自己的研究画像；修改后重启服务。画像的公开参考页面和核验日期保留在配置中。

## 单篇动机、实验与组内比较

打开论文详情，点击“开始动机与实验核对”。系统按需获取可提取全文，再使用自己的 Codex（默认 `gpt-6.1-sol`）整理研究动机、问题与核心主张，并逐项列出对应实验、正文证据摘录、可核验块编号、支撑程度及缺口。证据位置或摘录未通过正文核验时降为证据不足。该判断仍是 AI 对已取得正文的分析，不能替代复现，也不代表论文普遍正确。

没有可提取全文时，页面明确显示“证据不足”，不会用摘要补写实验支撑。HTML 全文无需额外依赖；PDF 可选使用本机 `pdftotext`，或安装 `pypdf`。两者均不可用、扫描件没有可提取文字、来源限制访问时，保留失败说明。重新分析会取得当时可用正文；未锁定历史版本的全文不能当作原周报窗口内版本，结果保留取得时间、来源及文本摘要指纹。

组内比较只使用实际取得的基准正文，排除论文与自身比较。每项包含来源、任务、数据、方法、监督条件、评价、可比性、未知项、可借鉴点及最小验证实验。找不到基准全文时明确列出缺口，不按论文标题猜测方法。旧周报可直接打开详情执行核对；失败重试保留上次成功结果。Markdown/JSON 导出包含已保存的核对结果。

## 收藏论文与代码的跨周追踪

收藏后的论文可在阅读清单中启用跨周追踪；旧浏览器收藏会尝试迁移为本机持久追踪目标。追踪同时保存论文快照，因此旧周报不存在时仍可注册。浏览器收藏/已读标记与服务器追踪分别保存；停止追踪后刷新页面不会自动重新注册。每份本机数据库最多追踪 50 篇论文、每篇最多 5 个 GitHub 仓库。同一 arXiv 论文的版本与题名变化合并为一个目标。

阅读清单的“跨周追踪”区域可手动检查。论文页面发现的仓库只是候选；后续成功检查发现新候选时会留“待确认”提醒，确认关联后再统计代码状态。README 占位仓库不算已具备实现。代码状态、README 中的权重/数据链接、arXiv 版本、OpenReview 状态、仓库默认分支提交和 release 会保存在本机；链接存在不等于内容已下载、许可已核验或代码已复现。

每个资源首次成功检查只建立基线，后续实质变化保留前后值、检查时间与历史；GitHub `updated_at` 和状态说明文案变化不当成代码更新。网络失败保留已有状态并显示错误，不改为未开源。编辑/移除仓库会重建相应基线，不把配置变更报成新开源。

服务运行期间会约每分钟检查是否达到 24 小时周期；到期且没有其他任务运行时执行本地检查。生成新周报时也会检查已有追踪目标。关闭网站服务后不会后台运行，电脑休眠或断网期间也无法保证准点检查；下次运行时继续。页面保留累计变化历史；周报导出只列本次检查新增变化。

## 数据、隐私与导出

报告、设置、缓存、论文集基线、单篇核对结果及跨周追踪目标/历史保存在本机 `data/` 下的 SQLite 数据库。个人阅读清单和已读标记另保存在当前浏览器本地存储中。Markdown 和 JSON 导出在页面中下载。选用 Codex 时，筛选后的公开论文摘要、公告及团队公开研究画像会通过 Codex 发给所选模型；主动进行单篇核对时，还会发送所取得的论文及基准正文。不要把私有内容填入补充来源。分发给其他成员时，只复制源代码包；本地 `data/` 不应随包分发。

## 排查问题

- 页面打不开：检查启动窗口是否仍在运行，并使用窗口中显示的地址。直接运行 `app.py` 遇到端口占用时，可改用 `python3 app.py --port 8766` 或启动脚本自动选择端口。
- Codex 未连接：确认 CLI 已登录，路径指向可执行文件，设置的模型可用于当前账号。
- 来源失败：查看报告中每个来源的具体错误；代理、防火墙、DNS、接口限流和来源改版都可能影响抓取。重试不会清除已有报告。
- 没有本周结果：先检查来源是否成功，再扩大日期范围；空结果不表示该方向没有研究活动。
