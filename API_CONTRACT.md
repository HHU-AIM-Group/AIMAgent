# AIM Radar local API

Server listens on 127.0.0.1:8765. All API responses are JSON except exports. GET `/api/bootstrap` returns `{profile,settings,codex,reports,active_job,latest_report,csrf_token}`. Reports list is newest first. Profile directions are objects with `id,name,description,keywords,anchors`. Settings include `model` (default `gpt-6.1-sol`), `codex_path`, `sources` object of booleans (`huggingface,arxiv,openreview,proceedings,news`), `openreview_venues` array (`ICLR,ICML,NeurIPS`) and `extra_feeds` array of public https URLs.

POST `/api/runs` `{start:"YYYY-MM-DD",end:"YYYY-MM-DD",use_codex:true}` → 202 `{job}`; GET `/api/jobs/:id` → `{job}`. Job `{id,status,progress,stage,message,report_id,error}` status is queued/running/completed/failed. One active run at a time (409 otherwise). Max window 14 days. GET `/api/reports/:id` → `{report}`; GET `/api/reports/:id/export?format=markdown|json` returns attachment. POST `/api/settings` accepts settings fields above → `{settings}`. POST `/api/codex/test` → `{codex}` (bounded real login/status check). GET `/api/health` → `{ok:true}`.

Mutations require `X-CSRF-Token` from bootstrap and `Content-Type: application/json`; Origin must match local server when present. Error payload `{error:"human readable"}` and suitable HTTP status. No auth credentials exposed.

Report `{id,start,end,created_at,status,summary,analysis_mode,papers,news,conferences,sources,warnings}`. `analysis_mode` codex/heuristic, status completed/partial. Each paper/news item has `{id,title,url,abstract,summary,why_it_matters,directions:[directionId],score:0..100,source,sources:[{name,url,date_basis,published_at}],published_at,discovered_at,date_basis,kind,venue,status,related_work:[],suggested_action,authors:[],research_score,importance_score}`. Additional fields safe. `date_basis` distinguishes original_publication,updated_this_week,hf_featured_day,first_observed,official_publication. News can have zero direction matches. Source `{id,name,url,status,count,message}` statuses ok/partial/error/disabled. Conferences `{id,name,url,status,message,new_volumes:[],baseline:bool}`. Summary strings are based on abstracts/announcements, never full-paper review.

Defaults: Asia/Shanghai Monday→today; frontend may send dates. No fabricated default report. Poll jobs every 1.5–3 seconds. Errors/failures retain previous reports.

## On-demand full-paper analysis

POST `/api/analysis` `{report_id,item_id}` (or `{item_id}` for an existing stored item, or `{item:{id,title,url,directions?,arxiv_id?,pdf_url?,full_text_url?}}` for an old local bookmark) returns 202 `{job}`. News is rejected. GET `/api/analysis/:item_id` returns `{analysis:null|object}`. All mutations use the existing CSRF and loopback protections. Jobs share the single busy lock (409 on conflict), and now include `type:report|analysis|tracking`; analysis jobs additionally include `item_id`. Completed analysis jobs expose `analysis`, not `report_id`. Results persist in SQLite and are copied to matching retained report items as `research_analysis`; old reports without this field remain valid.

Analysis `{item_id,status:completed|insufficient,created_at,full_text,motivation,problem,claims,anchor_comparisons,limitations,judgment_basis?}`. `full_text` contains `{status:available|unavailable,url,format:html|pdf|null,message,fetched_at?,text_sha256?,excerpt?,truncated?,version?,version_note?}`. A fresh on-demand target retrieval bypasses the HTTP cache; anchor retrieval may use its one-day cache. Version is null unless the retrieved URL explicitly pins a version, and `version_note` labels this as the text obtained at analysis time rather than the historical report week. The complete text is not sent back to the browser. Retrieval supports arXiv HTML then PDF, OpenReview PDF, and explicit HTML/PDF URLs. PDF extraction uses an already installed `pdftotext`, falling back to already installed `pypdf`; neither is installed automatically. Recognizable body/evaluation/references text is required. A landing page/abstract is insufficient, so claims remain empty and no experimental support is asserted when full text is unavailable. `completed` means analysis ran, not that claims were proven.

Claim `{claim,experiment,evidence_location,evidence_quote,support:supported|partial|unsupported|insufficient,gaps:[]}`. Location is an extraction block ID such as `P0001` (1200-character source blocks), not an invented PDF page/section. Both location and verbatim quotation (normalized whitespace) are checked against that block; a mismatch forces `insufficient`. Judgments are explicitly AI assessments of the retrieved experimental conditions, never reproduction results. If extraction is truncated this appears in metadata; unprovided evidence cannot be assumed.

Anchor comparison `{anchor,source_url,evidence_basis,task,data,method,supervision,evaluation,comparability,unknowns:[],borrowable_points:[],minimal_experiment}`. Dimension strings must explicitly identify target and anchor conditions. Only up to two same-direction anchors are attempted, excluding the same arXiv work. Actual retrieved anchor full text and a verified profile `anchor_sources`/`anchor_works` link or an identified team directory link are required. Missing anchor documents produce a limitation, not imagined comparisons. Empty comparisons are expected when no anchor text is available.

## Persistent cross-week tracking

GET `/api/tracking` → `{items,changes,last_checked_at}`. POST `/api/tracking` `{report_id,item_id,tracked:true|false,repositories?:[],confirmed?:false}` → `{item}`. The same item lookup/bookmark snapshot forms as analysis are supported. `repositories` are exact `https://github.com/owner/repo` addresses (maximum five); `confirmed:true` means the user confirms their association with this paper. Targets are deduplicated across title/version changes using canonical arXiv identity. At most 50 tracked papers are accepted. Removing tracking removes that active target; the global historical change log remains retained. Passing `repositories:[]` removes repository monitoring. Changing repository targets or their association confirmation resets the corresponding resource/repository baseline; that configuration edit is not reported as opening or closing code. A known state becoming unknown is not a confirmed source change.

Tracking item `{id,item,tracked:true,confirmed,created_at,last_checked_at,repositories:[],snapshot:null|object,changes:[],errors:[]}`. Snapshot `{arxiv_version:null|string,openreview_status:null|string,repositories:[],candidate_repositories:[],code,weights,data}`. Resource `{status:unknown|not_found|placeholder|available,url,message}`. `available` for code means recognizable implementation files were found, not execution/completeness verification; README-only repos are placeholders. Weights/data status only records explicitly discovered artifact links, not verified downloads/licenses. Unknown means insufficient information; `not_found` only means no verifiable code link was discovered in successfully checked pages, never that code is not open source.

Discovered HTML GitHub links are only `candidate_repositories:[{url,confirmed:false,evidence_source,message}]`; references may point to other authors' code. They are not automatically fetched, associated, or used for code-open notifications. Explicit repository targets are checked for default-branch commit SHA and latest release tag. Only confirmed repository associations drive paper code status. Repository snapshot `{url,default_branch,commit_sha,release,release_url,code,weights,data,confirmed,evidence_source}`. Changes in repository metadata `updated_at` do not count as new code. New SHA means the repository has a new commit; it does not establish an algorithm change.

POST `/api/tracking/check` `{}` → 202 `{job}`. Completion exposes `job.result` with the same tracking state. Runs check all tracked targets. The local service also checks when at least 24 hours elapsed (a 60-second scheduler while the server runs), and after generating each new report; no background checks occur when the local server is closed. First successful observations establish per-resource baselines and do not emit new-change notifications. Failed requests preserve prior successful state and add `errors:[{source,message}]`; failures never imply resources were removed or closed. Changes `{id,item_id,at,field,before,after,message}` persist in SQLite (500 global, 100 per target); resource notices compare substantive status/URL only. Jobs and network calls are bounded; API failures leave saved reports intact.

## Publisher VPN compatibility

The fetcher preserves public HTTPS-only URLs, port 443, no credentials, DNS checks, TLS certificate verification, and redirect checks on every hop. Some local VPNs resolve public sites into RFC2544 `198.18.0.0/15`. That range is accepted only for the exact built-in publisher/API hostnames in `sources.FAKE_IP_PUBLISHERS`; no suffix/wildcard matching, arbitrary custom domains, literal fake IPs, RFC1918, loopback or link-local addresses are exempted. This supports the local VPN without allowing general private-network fetching.

Markdown exports include saved `research_analysis` details and the current check’s `tracking_updates` changes when those fields exist. Historical reports without them omit those sections.

Candidate link discovery records `snapshot.discovery_success` and `discovery_repository_urls`. A discovery succeeds when at least one paper HTML page is fetched (a PDF alone does not qualify); previous candidate URLs are retained across individual source failures. New candidate URLs between two consecutive successful discovery checks create `field:candidate_repository` changes with message “新发现候选仓库链接，请确认是否属于本论文”. Initial success, first success after a failed discovery, and repository configuration changes establish a baseline only. Such events never assert that paper code is open source or belongs to the paper.

If a repeated analysis cannot obtain sufficient new full-text evidence while a completed result already exists, the new job fails with an explanation and leaves the previous SQLite/report analysis intact. An initial insufficient analysis still saves its explicit insufficiency result.
